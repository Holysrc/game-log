# GAUNTLET — сессия развития Game Log

Прочитай CLAUDE.md полностью. Он — закон. Затем прочитай docs/PROGRESS.md,
если существует, и продолжи с места остановки. Работай в ветке
`gauntlet/<сегодняшняя дата>`.

Цель сессии: провести проект через этапы ниже. Каждый этап закрывается
только когда его критерии приёмки зелёные и субагент-критик принял
результат. Не переходи к следующему этапу с красными тестами. Если этап
блокирован неразрешимо — зафиксируй в PROGRESS.md причину, откати этап
до последнего зелёного коммита и переходи дальше.

## Этап 0 — Сбруя (без этого не двигаться)

- npm-проект, Playwright, локальный статический сервер.
- `tests/fixtures.ts`: генератор 1500 реалистичных игр (сеяный PRNG).
- Смоук-тесты ВСЕХ пунктов §9 CLAUDE.md на текущем index.html,
  вьюпорты 390×844 и 1280×800, языки RU и EN.
- Скрипт `npm run shots` — скриншоты ключевых экранов в `shots/`.
- Приёмка: все смоуки зелёные на НЕИЗМЕНЁННОМ текущем коде. Если
  смоук падает на текущем коде — это найденный баг: чини код, не тест,
  и записывай в PROGRESS.md.

## Этап 1 — Модуляризация со страховкой

- Разнеси код по `src/` (TypeScript, модули по смыслу: data, sync,
  import, ui, i18n), Vite со сборкой в самодостаточный dist/index.html.
- Поведение не меняется ВООБЩЕ. Приёмка: полный смоук зелёный на
  сборке; ручной diff бандла и старого файла по функциональности;
  размер бандла ≤ старого ×1.5.
- GitHub Actions workflow: сборка и деплой dist/ в Pages (файл создать,
  но не пушить — пользователь включит сам).

## Этап 2 — Экран «Итоги» (главная фича сессии)

Кнопка в шапке → полноэкранное FF-окно со статистикой:
- переключатель года (все годы с прохождениями + «Давно» + «Всё время»);
- за период: пройдено игр, суммарные часы (из time), средняя оценка
  (звёзды), топ-3 жанра, топ-3 платформы, разбивка по лончерам;
- «Игра года» — самая высокая своя оценка (при равенстве — больше часов);
- самая длинная игра по часам; серия года (больше всего прохождений);
- пустые состояния для периодов без данных; RU/EN; мобайл и десктоп.
- Оформление — как экран результатов миссии в FF: строки «параметр …
  значение» с моноширинными цифрами, золотые акценты, никаких графиков-
  библиотек (максимум CSS-бары).
- Приёмка: смоук + скриншоты приняты критиком на обоих вьюпортах.

## Этап 3 — Умный кубик

- Тап по 🎲 открывает маленькое FF-окно фильтров: жанр (из имеющихся),
  community score ≥ N, только «есть в библиотеке» (source не пуст),
  только нетронутые (time == 0), серия.
- Фильтры запоминаются на устройстве; кнопка «Бросить» крутит выбор
  ТОЛЬКО по отфильтрованному пулу; пустой пул — честное сообщение.
- Быстрый бросок без фильтров: долгое нажатие или вторая кнопка.
- Приёмка: смоук-сценарии (фильтр по жанру, пустой пул, сброс фильтров),
  критик принял окно на мобильном.

## Этап 4 — Полировка под критиком (цикл)

Запусти цикл: скриншоты всех экранов → субагент-критик → правки → снова.
Минимум три итерации или до вердикта «принято» по всем экранам.

Чек-лист критика (жёсткого, придирчивого):
- отступы кратны 4px, ничего не прилипает к краям;
- ни одного горизонтального переполнения на 390px (историческая боль
  проекта — проверять панель настроек и чипы карточек особо);
- тап-цели ≥ 44px; контраст текста читаем на градиенте;
- sticky-заголовки не наезжают на контент; пустые состояния везде;
- обе локали: английские строки не вылезают из кнопок;
- стиль един: один радиус, одна палитра, serif только в заголовках;
- вопрос критика: «похоже ли это на экран из Final Fantasy, или на
  бутстрап-админку с синим фоном?» Если второе — отклонить с
  конкретным списком правок.

## Этап 5 — Офлайн и производительность

- Service worker: приложение открывается офлайн (кэш app-shell,
  синк деградирует в «офлайн · локально»).
- Перф на фикстуре 1500 игр: рендер < 150 мс, поиск без фризов
  (замерь и запиши цифры в PROGRESS.md).
- Приёмка: Playwright-тест офлайн-режима; бюджеты соблюдены.

## Правила сессии

- Реальный гист, токены и данные пользователя не трогать. Синк в
  тестах — мок.
- Подпроцессы: раздавай подзадачи субагентам (тесты, критик, миграция
  модулей) параллельно, но интеграцию в ветку делает один поток.
- После каждого этапа: коммит + обновление docs/PROGRESS.md
  (сделано / решения / проблемы / следующий шаг).
- Финал сессии: PROGRESS.md содержит краткий отчёт для человека:
  что готово, как запустить локально, что посмотреть глазами,
  что осталось.
