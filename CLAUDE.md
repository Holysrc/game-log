# Game Log — конституция проекта

> Этот файл — верховный закон репозитория. При любом конфликте между ним,
> промптом сессии и твоими идеями — побеждает этот файл.
> Язык проекта: русский (код и комментарии — английский).

## 1. Что это

**Game Log** — персональный трекер видеоигр одного пользователя (Андрей).
Одностраничное PWA в стиле меню Final Fantasy: синие градиентные окна,
золотой акцент, serif-заголовки. Задеплоено на GitHub Pages, установлено
на Android как приложение. ~1200 игр импортированы из Playnite.

**Короткий питч:** журнал сохранений всей игровой жизни — беклог, история
прохождений по годам, оценки и заметки — синхронизированный между ПК и
телефоном без сервера.

**Core test проекта:**
> Может ли владелец за 5 секунд с телефона одной рукой найти игру,
> отметить её пройденной и получить удовольствие от того, как выглядит
> его история?

Если фича не помогает этому тесту — она не нужна.

## 2. Приоритеты при неоднозначности

1. **Сохранность данных пользователя** (история прохождений незаменима);
2. целостность синхронизации через Gist;
3. удобство на телефоне (тач, одна рука, Firefox Android);
4. читаемость и цельность FF-стиля;
5. скорость интерфейса на ~1500 играх;
6. новые возможности.

Красота никогда не важнее данных. Фича никогда не важнее скорости.

## 3. Железные инварианты (нарушение = провал сессии)

### Данные
- Схема данных меняется ТОЛЬКО аддитивно: новые поля опциональны,
  существующие не переименовываются и не меняют тип.
- Поля записи игры: `id, name, status(backlog|playing|done|dropped),
  years[] (0 = «Давно»), oldCount, rating(1-5), cs, platform, source,
  genres, rel, time(сек), series, note, fav`.
  Корень: `nextId, updatedAt, games[], collapsed{}`.
- Любая миграция: (а) идемпотентна, (б) не трогает `updatedAt`,
  (в) покрыта тестом со старым фикстурным JSON.
- Импорт CSV из Playnite никогда не перезаписывает: статусы, годы,
  oldCount, rating, note, platform, source (кроме заглушки "Playnite").
  Всегда перезаписывает: series, cs. Добирает пустоты: genres, rel;
  time — только в большую сторону.

### Синхронизация
- Протокол Gist неизменен: файл `game-log.json` в приватном гисте,
  PATCH целиком, last-write-wins по `updatedAt`.
- Правило записи: push в удалённое хранилище только если локальный
  `updatedAt` новее. Открытие приложения и миграция НЕ бампают `updatedAt`.
- Токен и Gist ID живут в localStorage устройства и никогда не
  попадают в код, тесты, логи или коммиты.

### Продукт
- Итог сборки — ОДИН самодостаточный `dist/index.html` (инлайн CSS/JS),
  плюс manifest.json, иконки и sw.js (service worker для офлайна) рядом.
  Приложение обязано работать и без sw.js. Никаких CDN и внешних
  запросов, кроме api.github.com (синк) и script.google.com
  (опциональный синк); sw.js не перехватывает запросы синка.
- Работает офлайн после первой загрузки.
- Два языка: RU и EN, словарь TR в коде. Ни одной захардкоженной
  строки интерфейса вне словаря.
- Весь UI работает тачем; нативный datalist запрещён (не работает в
  Firefox Android) — только кастомные подсказки.

## 4. Вне скоупа (не делать, даже если очень хочется)

- аккаунты, серверный бэкенд, базы данных;
- внешние API метаданных (IGDB, HLTB, Steam) и обложки из интернета;
- фреймворки (React/Vue/Svelte) — только vanilla TS/JS;
- реклама, аналитика, трекинг;
- изменение протокола синка или формата гиста;
- редактирование чужих настроек Playnite / запись обратно в Playnite;
- мультипользовательность.

## 5. Технологии

- Разрешено: разбить код на модули `src/` + Vite + TypeScript,
  Playwright для тестов, GitHub Actions для сборки в Pages.
- Обязательно: сборка выдаёт самодостаточный single-file
  (vite-plugin-singlefile или эквивалент). Если сборка нестабильна —
  откат к текущему единому index.html, это валидный исход.
- Node LTS, npm. Никаких экзотических тулчейнов.

## 6. Стиль (FF-меню — дефолтная тема)

- Палитра ниже описывает ДЕФОЛТНУЮ тему. Альтернативные темы — оверрайды
  CSS-переменных через `data-theme` на `<html>` (см. `src/theme.ts`);
  выбираются в настройках, живут в localStorage устройства и в синк не
  попадают. Первая альтернативная тема — «Sega Genesis». Все инварианты
  вне палитры (радиусы, сетка 4px, тап-цели, типографика, serif только
  в заголовках) действуют в любой теме. Новые цвета в стилях — только
  через переменные, никаких захардкоженных заливок.
- Палитра: фон #0b1120; окна — градиент #2b3f8c → #182566 → #0d1544
  с белой рамкой #c9d3ee; золото #e9c46a; зелёный #8fd99a; голубой #8fa3d9.
- Заголовки: Palatino/Georgia serif, letter-spacing, UPPERCASE.
- Числа: моноширинные, tabular-nums.
- Карточка = «слот сохранения». Курсор ▶ у активной игры.
- Формы скруглены на 8px; чипы 4-5px; сетка отступов кратна 4px.
- Тап-цели ≥ 44px на мобильном. Никакого горизонтального переполнения.

## 7. Проверка качества

- Тестовые данные: генератор фикстур `tests/fixtures.ts` — 1500 игр
  с реалистичным распределением (годы, жанры, серии, «Давно», заметки).
  РЕАЛЬНЫЕ данные пользователя и его гист в тестах не используются НИКОГДА.
- Playwright: смоук всех фич из §9 на двух вьюпортах — 390×844 (телефон)
  и 1280×800 (десктоп), на обоих языках.
- Скриншот-цикл: после каждой визуальной правки — скриншоты обоих
  вьюпортов; субагент-критик (см. GAUNTLET.md) принимает или отклоняет.
- Перф-бюджет: полный рендер списка 1500 игр < 150 мс на десктопе;
  ввод в поиск не блокирует кадр > 50 мс.
- Консоль чистая: ни ошибок, ни ворнингов.

## 8. Git-дисциплина

- Работа в ветке `gauntlet/<дата>`. В `main` не коммитить, не пушить.
- Коммит после каждого зелёного этапа, сообщение: `stage N: <что сделано>`.
- Файлы-эстафеты: `docs/PROGRESS.md` (что сделано, что осталось,
  известные проблемы) обновляется в конце каждого этапа — следующая
  сессия начинает с его чтения.

## 9. Существующие фичи (регресс-лист, ломать нельзя)

Статусы и вкладки (Все/Играю/Беклог/Пройдено/Брошено/Каталог/Избранное);
группы по годам + «Давно ×N» со сворачиванием и sticky-заголовками;
селект «+ Прошёл в…» в любом контексте; звёзды + чип community score;
заметки (📝); платформа/лончер/серия с кастомными подсказками (тап по
подсказке НЕ сворачивает карточку); чип серии ❖ как фильтр; избранное ⚑;
сортировки; поиск + `#nodata`; умный кубик 🎲 (заголовок беклога +
вкладка): тап открывает FF-окно фильтров (жанр, cs ≥ N, «есть в
библиотеке», «только нетронутые», серия) с живым счётчиком пула,
фильтры хранятся в localStorage устройства, «Бросить» — по пулу,
пустой пул — честное сообщение, «Без фильтров» — быстрый бросок;
объединение дублей ⇆ (без сиквелов и одной серии); импорт Playnite CSV
по правилам §3; бэкап/восстановление JSON; Gist/Apps Script синк со
статусом в шапке; RU/EN (плюрализация RU: 1/2-4/5+); экран «Итоги» ▦:
периоды («Всё время»/годы/«Давно»), метрики БЕЗ часов в годовых
периодах (time из Playnite — общий за жизнь игры; часы и «Самая
длинная» только во «Всё время»), «Игра года/эпохи», «Серия года»,
дельта «К прошлому году» ▲/▼/=, CSS-график «По годам» с автоскроллом,
бары по жанрам/платформам/лончерам; темы оформления (§6): FF-дефолт +
«Sega Genesis», выбор в настройках, живёт на устройстве; офлайн через
sw.js; PWA manifest; десктопная сетка ≥860px с равной высотой карточек
в ряду; мобильная вёрстка без переполнений, тап-цели ≥ 44px.
